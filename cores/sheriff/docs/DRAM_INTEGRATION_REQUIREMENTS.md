# Production DRAM integration requirements

The joined CPU service proof supports a conditional functional chain, not production wiring. The next missing original-board input is **CPU_WR_RD generation, polarity and edge timing**, from the CPU-side driver to the video-board RAM-disable network. Its supplied constant1 in the joined test cannot become a production equation. Resolving that input is necessary, but does not settle the remaining video and service policies.

The existing production board uses the compatibility CPU with READY tied high (board77–82; CPU64–68). Its RAM has two simultaneous registered reads and one shared write path: CPU/debug at board109, bitmap at110, CPU write at116–117 and paused debug write at118–119. The new storage component serializes one logical address; the inferred physical DUAL_PORT primitive does not grant extra external access ownership.

A direct reuse of the joined crystal-enable formula during pause is invalid. Production freezes CPU phase under execution_pause (CPU18), whereas the fixture derives ce_xtal from that phase (joined33–34) and memory phases advance whenever ce_xtal is high (memory29). A frozen eligible phase makes the enable constant1 and advances slots every master clock; another phase makes it constant0. User pause currently keeps raster running (board155–172), so physical memory/refresh phase must retain an independently defined crystal cadence. Explicit debug_freeze preserves checkpoint time and needs a separately specified freeze policy. This assessment chooses neither a new clock origin nor a pause fix.

Hiscore is a timed interface with no RAM-valid/acknowledge input (vendor53–75). CHECK_HOLD/WRITE_HOLD default to2 master clocks and are configurable (vendor79–85); checks sample data_from_ram within their hold windows (598/626), and writes hold ram_write for WRITE_HOLD (688–720). Pausing CPU alone does not reserve video slots. A new physical service bridge must meet the configured read/write deadlines or explicitly adapt that interface, including same-address video/debug collisions and the return to CPU. The joined test had pause=0 and no debug owner.

Reset has two distinct contracts. Current production RAM starts at deterministic zero and survives warm reset (board40–50); new storage is uninitialized and reset clears control/DO validity without erasing bytes. Cold initialization needs an explicit compatible policy before replacement. Storage/readback must cancel incomplete transactions without phantom writes, preserve warm RAM and re-establish the active CPU byte before resuming. The phase component's reset origin is synthetic; the source evidence does not establish resetting the physical memory counters on CPU reset or stopping refresh during download/pause. FPGA block RAM does not itself need4116 retention refresh, but that fact does not qualify the original refresh waveform.

The smallest production checklist is:

1. Prove the raw CPU_WR_RD driver, polarity and transitions into the existing disable equation; retain DBIN/WR/A14 continuations separately until that bridge is proven.
2. Replace the board CPU instance with n8080_cpu_ready; connect control to raw address/WR/SYNC/phi1 and physical slot/H/V pins; connect RAS/CAS/WE/address/DI to storage, DO to readback and readback READY to CPU. Keep the existing IRQ/I/O/ROM DIN priority and remove abstract RAM commits only after their pin-event replacement is qualified.
3. Supply pause-safe physical phase inputs and source-supported dynamic video H/V, DO capture and pixel/serializer ordering. Define CPU/video same-byte old/new-data behavior at their actual sampling edges.
4. Add a hiscore/debug service adapter with explicit slot ownership, bounded timed-interface service and CPU capture restoration. Preserve both user-pause scanout and debug-freeze checkpoint behavior.
5. Define deterministic cold initialization, warm-reset preservation, transaction cancellation and memory-phase/refresh behavior across pause, reset and downloads.
6. Only then add n8080_memory_phases, n8080_dram_control, n8080_dram_storage and n8080_ram_readback through files.qip. Qualify changed production RAM/video/persistence/IRQ/pause behavior and current fit/resources/timing. Component M10K inference already meets its logical-access/resource purpose; physical SINGLE_PORT is not an additional gate.

The existing joined proof passed five named synthetic reset origins using explicit CPU_WR_RD=1, fixedH19/V166 and the rounded shared-clock projection: each had7valid RAM read captures and8write services, correct committed bytes, stable waits and no unsupported edges. It covers the ordinary STA/LDA/MOV/LHLD/SHLD/CALL/RET fixture. It does not cover dynamic video, pause/service borrowers, interrupt/I/O boundaries, cold initialization or physical timing.
