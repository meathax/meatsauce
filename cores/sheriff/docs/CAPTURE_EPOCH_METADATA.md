# Future capture epoch metadata

The observers now retain epoch observations and the exact capture scripts used by future runs. This changes diagnostics only: existing reset hold, tick origin, raster stepping, CPU pins, input delivery, MAME taps and frame callback order remain unchanged. No historical capture gains missing provenance, and no physical common-origin qualification follows from this patch.

`sim/board_harness.cpp` writes `capture_epochs.csv`. `external_reset_release` records tick 0 immediately after the existing reset assignment, before another evaluation. `excluded_reset_clocks` counts the ROM-loading steps plus the existing 1,000 reset-hold steps. H/V and CPU pins describe the last evaluated state at that assignment. `first_observed_sync` and `first_observed_dbin` record the first asserted public pin sampled at the existing clock-low evaluation, before the loop's rising edge. They are pin observations, not instruction tags or reconstructed edges. Divider phase is explicitly `unexposed`: the board exports no phase port, and this patch adds none. Pause-check mode retains only its release record because it uses its existing separate stepping path.

`sim/mame_capture.lua` writes `capture_epochs.csv` and `capture_epoch_sources.csv`. The first event observes CPU PC, existing beam reconstruction, and scheduler time at the original autoboot capture start. It does **not** observe a logical reset edge: MAME initialization has already occurred. The reset-edge flag remains false. Further records occur inside the existing frame callback. Seconds/attoseconds and the decimal scheduler timestamp are retained with their observation site. MAME's `device_scheduler::time()` selects an active timer expiration, executing CPU local time, or global base time; Lua does not expose which context is active here. `timestamp_kind=scheduler_time_context_unexposed` preserves that limit. No new reset calls, taps, notifiers or CPU callbacks are installed.

`tools/mame_capture.ps1` freezes Lua and launcher bytes into the run's `capture_source/` directory before starting MAME. The absolute frozen Lua path becomes the autoboot argument; its SHA256 and the launcher SHA256 are inherited by Lua in two dedicated environment variables, restored when the launcher returns. `capture_features.json` and `exit.json` use those retained hashes and paths instead of hashing later current aliases. `launcher_invocation` identifies the actually invoked launcher path; the launcher snapshot preserves its bytes, rather than claiming that the snapshot itself was invoked. A snapshot collision with different content fails before launching. With `-WaitForExit`, `capture_source_verification.json` verifies both frozen files and the invocation path remain byte-identical before treating provenance as qualified. Without waiting, terminal stability and runtime exit remain unqualified. Manual Lua starts without supplied hashes write `unavailable`, not an inferred source identity.

Static verification and exact source hashes are retained under `_checks/agent-capture-epochs-20261010/`: `before/` contains original observers, `observer.diff` contains the grouped change, `receipt.json` records syntax exits and unchanged clock/reset/callback counts, and compiler logs retain failures or limitations. The documentary common-origin recovery additionally freezes pre-edit Lua/launcher bytes under `_checks/agent-common-origin-20261010/context-before-epoch-metadata/`, retaining the normalized first-pixel export separately from its original CRLF export.

The next already-required paired run must check the generated sidecars, frozen-script hashes and process exit receipts. Native pin epochs and MAME scheduler observations must remain explicitly different timestamp kinds. A future source-supported implementation can then qualify a common origin; these metadata additions select no numerical offset and do not repair the existing field-66 or field-2760 negatives.
