# Conditional DRAM storage model

The isolated `rtl/n8080_dram_storage.sv` implements the source-declared event semantics in [DRAM_DATA_ORDERING.md](DRAM_DATA_ORDERING.md). Its inputs are a master clock, explicit RAS/CAS/WE levels, seven physical multiplexed address pins and DI. CPU arbitration and physical timing remain caller obligations.

A RAS fall stores the row; a supported CAS fall stores the column. An early write captures DI at CAS fall when WE was already low. A delayed write captures DI at a later WE fall with RAS/CAS low and a valid transaction. Address and DI changes without a write edge cannot commit. Orphan CAS edges, closed rows and stale columns cannot write. Simultaneous RAS/CAS or WE/CAS falls are exposed by `unsupported_event` and rejected.

The array has one synchronous port, 16384 eight-bit words, and no reset loop or initialization. Its index is `{column,row}`. A CAS read requests the payload at that master-clock edge; held DO/read-valid update on the following edge. CAS rise releases validity after another clocked consumer has sampled old state. RAS rise alone closes the row while retaining valid DO until CAS rises. Reset releases control/output and preserves RAM. This old-state ordering is a functional abstraction, without an electrical hold guarantee.

Run `tools/qualify_dram_storage.py` with the bundled Windows Python interpreter. It freezes sources and existing32 source-derived edge rows, then builds/runs the isolated top in explicit Ubuntu WSL. The receipt is [sheriff_dram_storage_native.json](evidence/sheriff_dram_storage_native.json); the successful immutable run directory is `_checks/agent-dram-storage-20261010-v2`. The focused regression seeds selected endpoint and CPU/video addresses through pin writes; it checks reads, early/delayed writes, CAS release, old-state consumer capture, orphan/stale transactions, ambiguous-edge rejection and reset retention. It replays both supplied CPU_WR_RD branches without deriving phases again.

A successful receipt requires actual build/native/workflow exits0, zero functional mismatches,64 frozen before/after pin points,6 reads,0 writes,2 orphan CAS events and4 old-state video captures. The runner records source/fixture/model hashes and audits them after execution. No exhaustive address walk or whole-board ROM run is part of this test.

The module stays outside production QIP. BRAM inference is intended by the synchronous single-port form; device fit is unqualified. CPU_WR_RD generation/polarity, dynamic arbitration, CPU address/DI/WR setup and READY, row capture near counters, serializer setup/hold, refresh and exact Sheriff DRAM revision/vendor/grade/load remain unresolved. This test qualifies isolated event semantics and delivery ordering only.

The first retained stage, `_checks/agent-dram-storage-20261010`, built with exit0 but native/workflow exited1 because Verilator rejected a second model sharing an already advanced context. The C++ harness now gives each Drive an independent context. Storage RTL stayed unchanged; the corrected v2 run passed177checks with actual build/native/workflow exits0. Native source snapshots and the original qualified runner remain immutable.
