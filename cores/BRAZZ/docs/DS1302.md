# Crystal System GPIO / DS1302

`rtl/soc/vr0_gpio.sv` implements the board's latched output at SoC offset `0x2004` and RTC input at `0x2008`. CE, SCLK and data use GPIO bits 24, 25 and 28. Latched writes honor byte strobes; a low-byte write preserves the high-byte serial pins. The CPU bus delivers these transactions to genuine RTL.

`rtl/soc/ds1302.sv` implements LSB-first commands, rising-edge input, falling-edge output, output release, single-byte and burst access, 31 RAM bytes, clock halt, write protection and BCD timekeeping. The calendar includes month/leap-year boundaries, year wrap, weekday and 12-hour AM/PM transitions. Clock-burst writes apply only after all eight bytes arrive; incomplete bytes/bursts abort on CE falling. Trickle-charge register readback is retained; charging is a physical power function.

The [Analog Devices DS1302 datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/DS1302.pdf) governs behavior where the [pinned MAME implementation](https://github.com/mamedev/mame/blob/mame0289/src/devices/machine/ds1302.cpp) is incomplete: 12-hour mode, clearing write protection, eight clock-burst bytes, atomic burst commit, and continuous reads. MAME's serial bodies remain unchanged in the independent test oracle. No software RTC executes inside the board model.

## Clock, seed and battery state

- Production seconds use exactly 85,909,080 system clocks. Seed and seconds writes restart the sub-second phase.
- Cold defaults are 2000-01-01, Saturday, 00:00:00. The HPS seed port packs seconds/minutes/hours/date/month/weekday/year in bytes 0–6, in DS1302 register encoding.
- Indexed state bytes 0–8 expose the clock/control/trickle registers; bytes 9–39 expose RAM. Startup restore and seed are accepted while CE is inactive. Warm serial reset preserves calendar/RAM, and timekeeping continues during serial transfer.
- The current boot diagnostic uses cold initialization on reset. Final wrapper work must distinguish warm reset from power initialization and connect HPS seeding/persistence; those features are not yet wired or hardware-validated.

## Evidence and limits

`python -X utf8 scripts/sim.py gpio` passes 14,099 checks, including all RAM addresses, common MAME serial transactions, datasheet-specific behavior, calendar transitions, coherent read snapshots, halt, restore and warm reset. The unit bench accelerates a second to 64 clocks and checks its exact boundary. Its final replay uses 1,746 real game GPIO rows with a deterministic halted RTC seed; captured wall-clock-dependent RTC output bits are not asserted as that seed. GPIO latch reads are checked against the capture, and RTC serial reads against the independent MAME oracle. See `docs/rtc_reference.json` and `docs/simulation_gpio.json`.

The integrated BIOS run passes the former GPIO boundary. The old 50-million-clock budget expired after 2,591,707 matching instructions; with a larger diagnostic budget, real cartridge code reaches 8,233,974 compared retirements / 154,545,349 clocks, then the CPU deliberately faults on unresolved `MVTC R0,CR5` at `0x020820c4`. R0 is zero. MAME leaves MVTC/MVFC empty, so it cannot establish these register semantics. The latest boot report exits 1. Full cold boot into attract, sound and gameplay remains pending.
