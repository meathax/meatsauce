# MiSTer frontend audit

> **Status correction (2026-10-06 audit):** the intro, Refresh and Save-on-OSD rows and the Release blockers below describe the earlier diagnostic-raster top level and the `MVTC R0,CR5` stop. Production `CrystalSystem.sv` now uses `cs_crystal_platform`, `cs_nvram_host` (not `cs_nvram`, which is simulation-only) and the real scanout; `cs_diagnostic_video` is not in `files.qip`. The CPU no longer stops at `MVTC`. Remaining blockers are in plan.md (timing closure, qualified cold boot, pixel-exact attract/gameplay, sound, persistence/RTC, hardware).

The Crystal of Kings (`crysking`) is the only supported project target. **The game is still not bootable.** The top level now drives an explicitly labelled diagnostic raster and stages the frontend components. This does not pass the full simulation gate in `plan.md`, authorize an RBF build, or establish hardware operation.

## Release blockers

The real CPU still stops at unresolved `MVTC R0,CR5` semantics. The production SDRAM/DDR ROM loader, actual game board in `emu`, framebuffer display-start/scanout, complete audio and full gameplay acceptance are unfinished. Input/pause outputs and the NVRAM CPU port are deliberately identifiable integration endpoints in the diagnostic wrapper. Merely loading ROM bytes via HPS cannot boot a game with these endpoints unconnected.

Do not bypass the CPU fault with invented instruction behavior. Connect the genuine board and its SRAM/input/pause endpoints, arbitrate gameplay DDR separately from the reserved rotation buffers, verify startup/download/memory-ready reset sequencing, and run the existing full-game gate before the final hardware phase. The current native CRTC sync assumptions and interlace handling still need physical evidence; passing a MAME-derived timing oracle does not establish wobble-free electrical video.

## Verification and provenance

Run the five `scripts/sim_mister.py` targets (`mister_controls`, `mister_nvram`, `mister_video`, `mister_rotate`, `mister_scale`), followed by `scripts/verify_mister.py` and `scripts/validate_mra.py`; `python scripts/build_mra.py --check` regenerates the primary and alternate-BIOS MRAs and compares each assembled stream byte-for-byte. Evidence is in `docs/simulation_mister_*.json` and `docs/mister_feature_verification.json`. NVRAM tests use the production 64KiB size; rotation uses a small asymmetric raster to verify every destination pixel, FIFO wrap/stalls/overflow and publication. Wrapper lint substitutes only HPS and Intel PLL modules and suppresses Verilator's procedural-wire diagnostic for the unchanged legacy `sys/hq2x.sv`; it is not timing closure or a full-system simulation.

`rtl/video/cs_video_freak.sv` retains the original MiSTer copyright/license header and records the source hash of `sys/video_freak.sv`. The local changes rename modules, add `ROTATE_90`, swap the two measured dimensions supplied to the unchanged integer-scaling arithmetic, and remove trailing whitespace. Other new modules are original GPL-3.0-or-later work. No pristine donor or `sys/` file was changed.
