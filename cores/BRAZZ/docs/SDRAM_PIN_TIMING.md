# SDRAM pin timing and simulation contract

Target frequency remains 85.90908 MHz. The declared provisional module is a 32 MiB x16 ISSI IS42S16160L, CL2, sequential BL2. Primary authority: [ISSI L datasheet](https://www.issi.com/WW/pdf/42-45S83200L-16160L.pdf), revision 0A1 (2024-07-01), AC table page 19 and initialization page 23. The table permits tAC up to 6.5 ns and requires tOH at least 2.7 ns; address/command/data setup and hold are 1.5/0.8 ns. Separate clock and data board flights are currently bounded provisionally at 0..0.5 ns each. Hardware module identity and these board bounds must be qualified before release.

The original discrete model returns DQ at T2/T3. A real CL2 chip starts beat 0 after T1+tAC and beat 1 after T2+tAC. The real-controller delayed-return regression exposed first-halfword replacement at two fast-return endpoints from the original fitted clock/pad paths. An ideal capture 2.4 ns earlier passes those eight points, but that experiment is disabled in production and is not a physical clock implementation or signoff.

Production now selects `SDRAM_REGISTERED_IO=1`. An input register captures DQ on the core rising edge; command, address, masks, output data and drive enable are registered on the falling edge. The forwarded SDRAM clock is in phase with the core clock. The donor remains pinned and unchanged. Its read queue uses latency 4 for the additional input stage; legacy diagnostics retain latency 3. No new PLL or frequency reduction is introduced.

A READ identified at core edge C0 prepares pins at C0+half period and is sampled at the following external rising edge. CL2 data is then captured by the input register at C3, donor first sample at C4, second sample at C5, and low-halfword/ACK assembly at C6. Physical clock/input delays must place both burst beats inside those windows. Actual setup and hold constraints use normal single-cycle relationships. There is no memory multicycle/false-path exception.

`CrystalSystem.sdc` defines the actual forwarded clock from the core PLL pin and constrains SDRAM DQ input max/min to 7.5/2.7 ns and address/control/data output max/min to 2.0/-1.3 ns. QSF requests input/output I/O-register packing. A fitting result is conditional on the declared chip/board profile; inspect actual packing and four-corner setup/hold, including register transfers and output drive enable.

`scripts/probe_sdram_io.py` reuses the production forwarded clock when present. It preserves the saved QSF/SDC and extracts actual per-corner clock-path differences and DQ path delays into a hashed native `profiles.txt`. Set `CS_SDRAM_TIMING_PROFILE` to that exact file when running `scripts/sim.py sdram_registered`; the eight delayed chip/pad endpoint tests must all pass. They verify mapped reads and every byte mask against actual modeled chip storage, so a cache hit cannot hide a physical write failure. Never reuse profiles from a different pin architecture as signoff.

The donor's 100 us startup wait is supported by the cited ISSI initialization diagram (100 us minimum); its integer timing rounds upward at this frequency. No startup-delay change was needed. Refresh retention and realistic command/deadline timing remain part of final source-matched cold boot, with no software or canned-frame substitutes.

`sim/memory/sdram_timed_port.hpp` now supplies the chronological return model to both the backend unit and `host_timed_checkpoint`. The new full-board target selects registered I/O and requires an explicit profile file plus selected row name. Its model preserves actual SDRAM storage/command checks and DDR waitrequest/delayed beats; it does not preload live game RAM. Checkpoints include pending nanosecond DQ returns, DQ latch and pin-cycle position. Profile contents/name enter the checkpoint identity and run metadata, so changing physical timing invalidates old checkpoints. A run against a failing fit remains diagnostic even when a selected endpoint works. All eight unit endpoints and source-qualified physical timing must pass before a full-board run is acceptance evidence.
