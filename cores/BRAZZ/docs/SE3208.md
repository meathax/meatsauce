# SE3208 implementation status

`rtl/cpu/se3208.sv` is the game's synthesizable architectural CPU. It fetches the
reset vector at byte address zero, fetches 16-bit instructions, executes register
operations and issues memory transactions through the board bus. CPU progression
uses `ce`; the bus adapter continues outstanding requests on every system clock.
Retirement includes exception entry so architectural state compares with one
MAME instruction.

The independent test oracle is mechanically extracted from pinned BSD MAME 0.289
source under `docs/reference/mame/src/devices/cpu/se3208/`. Architectural function
bodies are unchanged. Emulator integration becomes a sparse little-endian test
bus and inert debugger/log adapters. Generated C++ is ignored simulation output;
source/extraction identity is recorded in `docs/cpu_reference.json`. This oracle
is never the CPU in full-board simulation or hardware.

Implemented: eight general registers, PC/SR/SP/ER, reset vector, all memory
transfers, arithmetic/logical/compare/test, register moves, immediate/extension
chains, signed loads, shifts/multiply/sign extensions, status-bit set/clear,
conditional branches/calls/jumps, ordered mask push/pop and stack calculations,
SWI/IRQ/NMI/vector entry, and machine-event outputs including HALT's callback.
Byte/halfword/word accesses split at word boundaries with byte strobes, one
outstanding request and variable backpressure/latency. Bus errors stop visibly.

Reference quirks retained: address index zero means zero although R0 is an
ordinary arithmetic register; most E-extended memory offsets consume four low
bits after size scaling; E-extended LDI consumes four low bits; relative branches
add their offset before automatic PC increment. MULS uses the low word of the
reference's unsigned-operand product and updates only V/E.

Remaining constraints:

1. MAME's INVALIDOP, MVTC and MVFC handlers are empty (PC+2 only; E and all
   registers untouched). The 3,488 encodings that `sim cpu` pass 0 excludes are
   2,944 INVALIDOP, 512 MVTC/MVFC (FC00..FDFF) and 32 four-bit register indices
   outside the GPR array (EXTB/EXTS/JR/CALLR with bit 3 set; undefined behavior
   in MAME). Pass 2 of `sim cpu` now covers all of them: with `INVALID_OP_NOP=1`
   every INVALIDOP/MVTC/MVFC word retires bit-exactly as MAME's no-op, except the
   64 primary-vendor MVTC/MVFC words, which perform the implicit-R0 coprocessor
   transfer (MVFC additionally sets R0 to the reply; nothing else changes); the
   32 out-of-array indices must fault. Production default `INVALID_OP_NOP=0`
   faults on invalid/CCMD/GETC/EXC/LDC/STC words instead (checked by cpu_control).
   Firmware must show these are unneeded, or the default must be set to 1.
2. Zero-count shift helpers use out-of-range C++ shifts. The test adapter and RTL
   explicitly mask bit indices: right-shift carry from bit 31 and left-shift carry
   from bit 0 at count zero. This matches this reference runtime, not a guarantee
   of undocumented silicon behavior. Resolve exercised firmware divergences.
3. MAME charges a nominal single execution unit per instruction. This sequencer
   models functional handshakes, not a verified physical pipeline. Full board
   throughput, arbitration, prefetch/cache needs and deadlines require measurement.
   The combinational multiplier may require pipelining for FPGA timing.
4. `ENABLE_STATE_LOAD` defaults to zero and is enabled only for isolated unit
   comparisons. Board acceptance must cold boot with the production default.
5. No actual firmware/SoC, protection overlay, graphics, audio or game acceptance
   is demonstrated by these CPU unit results.

Evidence: `docs/simulation_cpu_decode.json` (65,536 opcodes),
`docs/simulation_cpu_execute.json` (1,017,344 register/flag cases),
`docs/simulation_cpu.json` (239,536 CPU instructions / 1,210 IRQ/NMI cases,
exact byte-write traces, reset program, stalls and bus fault).
