# Crystal System / The Crystal of Kings for MiSTer

Preparation project for BrezzaSoft's 2001 The Crystal of Kings (`crysking`). **Release candidate: timing-closed and simulation-verified, not yet validated on MiSTer hardware** (see `releases/README.md` and `progress.md` for the exact RBF, fit and evidence). The active top level (`CrystalSystem.sv`) now instantiates the real board platform (`cs_crystal_platform`: RTL SE3208, VRender0 SoC/GPU/SPU, DS1302, physical SDRAM/DDR transport, HPS ROM loader, SRAM persistence, native scanout/audio). The diagnostic raster is no longer in production. Cold boot, attract, gameplay and timing closure are still open; see plan.md.

The main implementation plan is [plan.md](plan.md); actual work goes in [progress.md](progress.md). [goal_prompt.md](goal_prompt.md) contains the next execution prompt. [Hardware notes](docs/HARDWARE_NOTES.md) and the [donor coverage map](docs/DONOR_MAP.md) record the research.

The MiSTer frontend now includes named controls/service inputs, all eight DIP positions, integer scaling, HDMI CW/CCW/180 rotation and an OSD-triggered 64KiB SRAM persistence component. These components pass focused simulation and are now wired to the real board (controls, pause, SRAM backup); full-game behaviour is unproven. See [the feature audit](docs/MISTER_FEATURE_AUDIT.md) for implemented paths, evidence and release blockers.

The official MiSTer template, nine pinned public donor/reference snapshots and audited local crysking/BIOS archives are staged. No compatible public SE3208 or complete VRender0 RTL was located; the CPU/SoC/video/audio/DS1302 logic is custom RTL under `rtl/`, still being validated against MAME. Donor presence is not an integration or license-clearance claim.

All game bring-up, attract mode, sound and gameplay must work in synthesizable RTL simulation/Verilator first. Quartus/RBF/deployment/MiSTer testing is the final phase. The root `CrystalSystem.qpf` is a renamed Quartus 17 template.

ROMs, credentials, local configuration and large donor snapshots are excluded from commits. Source revisions/provenance are recorded in `donors/manifest.json` and local donor directories. The original template license is retained; individual donor reuse/compatible licensing is resolved before RTL promotion.

Oracle: full vanilla MAME 0.289, with seven matching key reference files from `mame0289`. The eight MAME protection patches and reset workaround are explicitly documented. Copied scripts are generic scaffolding and need SE3208/board adaptation.

Preparation and plan include AI-generated work. Future implementation, validation status, third-party notices and material approximations must remain explicit. No release bitstream exists yet.

Development RBF (timing closed, not game-validated, not hardware-tested): `releases/CrystalSystem_20261006.rbf` (ignored by git; hash in progress.md). Cold boot, attract, gameplay, sound and persistence are still unproven.

MRAs: `releases/The Crystal of Kings.mra` (default AMG0110B BIOS) and `releases/_alternatives/_The Crystal of Kings/The Crystal of Kings (AMG0110D BIOS).mra`, generated by `scripts/build_mra.py` and checked with `scripts/validate_mra.py`; the assembled 50,462,720-byte stream is compared byte-for-byte with the staged simulation images (`python scripts/build_mra.py --check`). Users supply `crysking.zip` + `crysbios.zip` from MAME 0.289. See [releases/README.md](releases/README.md). Not hardware-validated.

Credits: the OSD's **Credits** entry (status bit 120) opens the FPGA-resident MeatCore Credits overlay on the native 320x240 raster; any button, key, mouse button or reopening the OSD closes it. Names come from [credits.txt](credits.txt) and are compiled into the RBF; see [docs/CREDITS.md](docs/CREDITS.md).
